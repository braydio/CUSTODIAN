- Change:
  1. Introduce `EnemyReactionController` + typed `EnemyReactionConfig`. The config owns exactly reaction-domain tuning: `hit_recoil_duration=0.12`, `stagger_duration=0.35`, `resists_light_flinch=false`, `posture_max=100`, `posture_recovery_delay=1.25`, `posture_recovery_rate=26`, `light_flinch_cooldown=0.70`, `crit_hit_duration=0.8`, `crit_recovery_duration=0.625`. Preserve Marine `resists_light_flinch=true` and Savage `stagger_duration=0.45` through typed scene config overrides/resources.
  2. Move the seven ordinary reaction/posture mutable facts into `EnemyReactionController`: stagger timer, recoil timer, posture current, posture-recovery-delay timer, light-flinch cooldown timer, ordinary critical-hit timer and critical recovery timer.
  3. Move `_apply_reaction` policy into the controller. It consumes already-classified `CombatConstants.HitStrength`, posture damage and narrow host queries such as ordinary-melee commitment. It owns posture break, INTERRUPT/HEAVY handling, Marine armor-deflect choice, light-flinch suppression/cooldown and ordinary recoil selection. Shared `_resolve_hit_strength_for_attack` and `stagger_damage_threshold` remain host/shared hit-classification authority.
  4. Move recoil/stagger/ordinary-critical lifecycle and ticking into the controller. It may request narrow host services for: cancel current combat commitments, halt movement, semantic reaction presentation, observability, and presentation-only armor/light-contact cues. It must not own SpriteFrames, BSM decisions, target selection or special-ability state.
  5. Replace direct duration writes in `apply_melee_impact` for Vigil Dagger finisher reactions (Grunt 0.33 stagger, Marine 0.22 recoil, Savage 0.20 recoil when no Savage special commitment) with semantic controller requests preserving those exact values. The attack-specific policy stays with the host impact adapter; only reaction state/timers move.
  6. Introduce `EnemyParryCritical` + typed `EnemyParryCriticalConfig`. Config owns the critical-opportunity contract values that are simulation data: minimum window 0.8s, capture range 72px, operator offset Vector2.ZERO. Presentation-only marker/ring offsets and optional-VFX toggle remain presentation/actor configuration unless live implementation proves a cleaner existing presentation owner.
  7. Move parry-critical simulation state into `EnemyParryCritical`: window timer, ENTER/HOLD/RECOVER/EXECUTING phase, phase timer, reserved attacker, monotonic execution token, once-only damage-consumed flag, execution root, execution direction, execution kind, standalone root and standalone-root-valid flag. The current execution-body original-position/captured state must leave `enemy.gd`; place it in the existing presentation controller or another presentation-only helper rather than making simulation code own sprite restoration.
  8. Keep all existing public Enemy façade APIs stable for current Operator/Falcon callers: `can_receive_parry_critical_from`, `get_parry_critical_rejection_reason`, `reserve_parry_critical`, Falcon reversal reservation, begin/set-frame/apply-damage/finish/cancel paired execution, execution anchor/offset/facing, `receive_parry_critical`, reticle/normal-targeting suppression. These delegate to the typed authority and narrow host/presentation services rather than exposing the concrete module to Operator.
  9. Keep actual HP mutation, BSM `on_damaged`, assault damage accounting, popup/UI updates, `die()`, corpse/loot and `_damage_result` on Enemy/NPA-6 side. `EnemyParryCritical` owns token validation and once-only consumption but must request one host `apply_paired_execution_damage(...)` service for the real health/death result.
  10. Preserve current parry-stagger façade semantics: ordinary melee and active special commitments are cancelled through their public APIs; posture/reaction state resets through `EnemyReactionController`; critical-open is opened through `EnemyParryCritical`; the requested one-step physical knockback remains host CharacterBody movement; BSM damage notification and presentation hooks remain host-owned.
  11. Preserve fixed-step priority. Parry-critical opportunity/execution suppresses normal behavior first; ordinary critical-hit reaction/recovery then stagger then recoil suppress in the same order; only after those clear does `StandardEnemyMelee.tick()` and ordinary behavior continue.
  12. Replace direct reaction/parry-private state reads in presentation/debug/validation with semantic typed queries such as `is_staggered`, `is_recoiling`, `is_crit_reacting`, `is_reaction_blocking_behavior`, `get_posture_status`, `phase_name`, `is_execution_active`, `get_debug_state`. Update debug spawn modes to request phase transitions through the parry-critical authority rather than writing phase fields.
  13. Keep presentation helpers (`_play_light_contact_visual_reaction`, armor deflect, flinch selection/FX, critical-open BREACH/countdown VFX, custom crit FX, authored critical animations) presentation-owned. The new controllers request them through narrow host/presentation hooks; they do not become animation backends.
