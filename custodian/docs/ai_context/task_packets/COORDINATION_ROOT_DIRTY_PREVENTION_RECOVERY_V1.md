## Zero-touch operational policy amendment (2026-10-24)

**Current planning chat:** https://chatgpt.com/g/g-p-6980439e55688191bcf65f31f1c02d06-custodian/c/6adb61f3-35fc-83ea-87ed-ba961c7b5925

The earlier manual-only preserve/recover boundary is superseded **only for lossless, proven-idle, fully checksummed, exact-owner ordinary root contamination**. The default UX must require no per-file repair command for a stray file or accidentally staged/tracked edit. This is a scoped user request, not an authorization to delete or rewrite ambiguous user work. Unsupported/unsafe states remain original and protected, while workstream claims and reviews proceed through independent worktrees and the authoritative remote `origin/main`.

**No liveness guessing:** a root file is eligible for automatic restoration only when no protected writer/transaction is active and exact source bytes, index and Git revision are unchanged across both capture and apply. When process ownership is unknown, don't auto-restore that file, and do not block disjoint work to await it.

**Storage:** rescue blobs and private receipts live under the resolved Git common directory (or a configured trusted independent local destination); never under tracked repository paths or `asset_drop/inbox`. Normal asset source ingestion must be performed by its own claimed Asset Pipeline V2 workstream, not by indiscriminately moving an accidental root file into runtime art folders. Fail closed on capacity; retain original.

**Prevention:** command wrappers that write implementation, art and packet artifacts assert a genuine dispatched task worktree. They must never silently write to attached coordination `main`. External editors that ignore wrappers are not fully preventable: safe auto rescue and continued worktree-based execution provide the fallback.

**No-worktree-stranding invariant:** local root being DIRTY/DIVERGED/UNKNOWN is not a reason to stop already-safe `origin/main` claims or unrelated worktree landings. Route read-only and coordination work via clean detached snapshot checkouts as needed, without bypassing existing dispatcher identity, claim refs, paired-review provenance, or remote conflict gates.
