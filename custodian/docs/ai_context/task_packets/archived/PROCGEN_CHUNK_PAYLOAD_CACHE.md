### Findings

- **R0-01** (`optional_improvement`, domain `implementation`, affected acceptance: none -- memory-shape observation only, not a correctness defect): `ProcGenChunkPayloadCache._tile_records` is keyed only by `tile: Vector2i`, not by `(tile, chunk_pos)`. `invalidate_chunk()` bumps the chunk's revision and drops cached chunk *membership*, but it does not proactively erase that chunk's stale `_tile_records` entries -- they are only ever overwritten lazily, on the next `get_tile_record()`/`revalidate_record_before_commit()` call for that exact tile. Correctness is unaffected: `get_tile_record()` and `is_record_stale()` both re-check the stamped `generation_id`/chunk `revision` against current identity before ever returning a cached record as a hit (confirmed by code reading `procgen_chunk_payload_cache.gd:120-141` and by the smoke's own stale-record assertions), so a stale `_tile_records[tile]` entry can never be served as a hit -- it is simply inert memory until the tile is next visited or a full `reset()`/`invalidate_all()` clears it. Total growth is bounded by total distinct generated tile count (not unbounded over time), since the dictionary key space is the map's own tile set. Disposition: `deferred` -- a correctness-neutral memory-shape optimization (e.g. sweeping a chunk's own tile keys out of `_tile_records` inside `invalidate_chunk()`), not required for this packet's acceptance and not worth a correction cycle.
