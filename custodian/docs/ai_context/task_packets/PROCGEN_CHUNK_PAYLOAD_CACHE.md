- Change: Implement one plain-data/`RefCounted` derived cache keyed by generation identity plus `Vector2i` chunk coordinate. Populate it lazily only for chunks that streaming actually requests or PREPARE needs; do not prebuild/cache the entire map. A cached chunk payload may hold deterministic chunk tile membership in the same canonical order `_get_chunk_tiles()` currently returns and reusable per-tile floor/wall PREPARE records derived from `_generated_floor_cells` / `_generated_wall_cells`. It must contain no Node, TileMapLayer, CanvasItem, Texture/Resource ownership, collision body, foliage node, road decal node, Callable into gameplay, or mutable lifecycle/queue state. Cached records are read-only derived views, never semantic authority.
- Change: Preserve reveal ordering exactly. `_queue_chunk_for_reveal()` must obtain a copy/view of cached canonical membership and still sort the request using the existing live `_streaming_reveal_priority(tile, center_tile)` at request time. Do not cache a final reveal order because center distance changes with player position and current region/wall semantics participate in the score. Immediate-radius reveal must preserve the old `_get_chunk_tiles()` deterministic iteration order. M3 continues receiving the same tile sequence through its one shared queue.
- Change: Route `_build_tile_reveal_prepare_record(tile)` through the cache so repeated PREPARE/re-reveal can hit a reusable current record. Every prepared record must carry enough generation/chunk revision identity for `_commit_tile_reveal_record()` to verify that the record is still current immediately before authoritative mutation. If its chunk was invalidated after PREPARE, COMMIT must rebuild/re-fetch the tile record from the latest canonical semantic state before painting. This stale-record defense is required because M3 may hold prepared Dictionaries across resume frames while live gameplay resumes; invalidating only the cache is insufficient if an older prepared Dictionary is already sitting inside M3's `_prepared` queue.
- Change: Add exact invalidation without creating a second mutation model. Before editing, inventory every live write/erase of `_generated_floor_cells` and `_generated_wall_cells` and classify it as (a) pre-cache/bulk generation, (b) late generation/finalization after streaming priming, or (c) runtime semantic mutation. Reset the full cache on generation/reset boundaries and after any bulk finalization boundary where that is simpler and behavior-preserving. For post-cache tile/rect mutations, invalidate only affected chunk entries whenever practical. At minimum this must cover wall destruction including `_refresh_wall_neighbors`, authored-scene/world-overlook floor/wall claims, terrain/floor/wall authority changes that can execute after cache population, and any other live post-cache semantic mutation found by the inventory. Presentation-only changes and runtime blocker overlays that do not change generated floor/wall source data must not invalidate semantic payloads merely because they affect COMMIT-time realization.
- Change: Do not cache COMMIT-time dynamic effects. `_reveal_road_piece_decal()` / road-surface classification and spawning, dressing-cluster child realization, `_should_place_foliage()` / foliage placement/removal, runtime wall collision body construction, horizontal overlays, shadows, navigation, macro visibility, and runtime blocker state must continue to execute from their current owners in authoritative reveal order. The cache can accelerate the stable input record; it cannot pre-decide the live outcome.
