# Architecture Ownership Map

Compact agent-facing map for current and target ownership. Use this with `custodian/docs/ARCHITECTURE.md` and `custodian/docs/ai_context/FILE_INDEX.md`.

## Core Ownership

- Persistent state: currently `GameState`, `InventoryManager`, `CognitiveState`; target is `game/state/persistent/*` behind compatibility facades.
- Transient campaign/run state: currently `GameState`, `GameStats`, and contract generation records; target is `game/state/run/campaign_session.gd`, `campaign_outcome.gd`, and `run_phase.gd`.
- Active world binding: currently `contract_world_loader.gd`, scene-local transition code, camera/navigation rebinding; target is `game/world/lifecycle/*`.
- Procgen construction: `proc_gen_tilemap.gd` is the façade/state host; terrain, intent, playability, foliage, encounter cadence, and pre-terrain required-cell/diagnostic/repair algorithms live in focused helpers. `encounters/encounter_cadence_planner.gd` owns data-only combat-pocket cadence; it never spawns actors or mutates geometry.
- Authored maps: currently `game/world/sundered_keep/`, `game/world/home/`, and gothic compound runtime files; target is `game/world/authored/<map>/` after explicit path migration.
- Non-player actor target architecture: `design/04_architecture/NON_PLAYER_ACTOR_RUNTIME_ARCHITECTURE.md` defines six behavior/lifecycle families plus the canonical Actor Facet Model (identity/provenance, traits/profile, relationship, perception, memory, decision policy, capabilities, abilities, physical state, presentation, lifecycle/persistence, command/interaction). The facet model is conceptual composition, not a universal `ActorTraits`/`ActorBrain` type. `enemy.gd` is the standard mobile combat-agent coordinator, never a universal NPC base; allegiance remains orthogonal runtime state.
- Combat simulation: shared contracts remain under `game/systems/combat/*`; actor-local controllers/abilities own bounded phase machines. `OperatorActionController` owns Operator action arbitration/priority/lifecycle, `OperatorGuardController` owns guard/parry/posture/break state, and `OperatorPresentationController` owns semantic presentation coordination over the selector/player/body-presenter stack. `operator.gd` remains the fixed-tick/movement chassis and compatibility facade while F0/F1-F6 extract the remaining loadout, melee, ranged, dodge, interaction and recovery domains. Enemy special abilities follow the same actor-hosted boundary.
- Commanded ally targeting: `ActorAllegianceComponent` owns `CombatDrone`'s semantic `operator_allied` relationship; `DroneManager` owns player input/order authorization; `DroneSquadState` owns squad mode/roster/reusable squad-local slots; `DroneTargeting` owns autonomous-hostile versus explicit-command eligibility; `CombatDrone` revalidates the selected source at each projectile commit and cancels stale burst rounds. `AlliedInfantryDroid` inherits this contract and owns presentation only.
- Enemy behavior: `EnemyBehaviorStateMachine` owns strategic state and movement goals; perception owns detection; objective sensor scores candidates; blackboard stores working memory; profiles tune behavior. `EnemyAnimationSet` plus `EnemyPresentationController` own semantic animation mapping/playback only. Actor-local ability modules own extracted special-decision/execution seams. `enemy.gd` remains the shared combat/locomotion host, reaction authority, compatibility surface, and disabled-BSM legacy fallback.
- Navigation/elevation: `NavigationSystem` owns path selection; `ProcGenTilemap` plus `ElevationMap` own movement legality. Ambient spawning remains exclusively `AmbientEnemySpawner` plus `AmbientEnemyCamp`, with loader markers adapting encounter-plan data.
- HUD/terminal presentation: currently `game/ui/hud/ui.gd`, `game/ui/terminal/*`, `game/ui/components/*`, `game/ui/minimap/*`; target keeps UI as read-only presentation plus explicit command requests.
- Debug/observability: currently `custodian/debug/*`, `DevObservatory`, `WorldHistory`, `SectorHeatmap`, validation scripts; target routes observability services under `game/systems/observability/` without becoming player UI.

## Overburdened Coordinator Files

- `custodian/game/world/procgen/proc_gen_tilemap.gd`: procgen facade, construction policy, roads, terrain integration, foliage, portals, authored claims, export helpers.
- `custodian/game/world/procgen/custodian_contract_map.gd`: contract seed/profile creation, candidate selection, acceptance metrics, final visual promotion.
- `custodian/game/systems/core/systems/contract_world_loader.gd`: runtime handoff, anchor rebinding, vehicles, relays, resources, ingress, authored destinations.
- `custodian/game/actors/enemies/enemy.gd`: standard combat-agent coordinator for shared combat/locomotion, host integrations, ability/reaction/melee façades, animation fallback, and behavior hooks. `components/enemy_lifecycle.gd` + typed config own health/death/damage results, one-time corpse payload and empty-corpse cleanup; `EnemyCorpseLoot` owns collection/rewards and `EnemyLootCarrier` owns captured resources. Marine Dash's complete phase authority and typed tuning live under `abilities/`.
- `custodian/game/actors/enemies/presentation/`: semantic animation-set and playback authority; presentation never owns hit timing or behavior state.
- `custodian/game/actors/enemies/abilities/`: actor-local special ability modules; Falcon Punch and Marine Dash own their complete phase/cadence/contact authorities with typed tuning, while Savage phases remain for later slices.
- `custodian/game/actors/operator/operator.gd`: fixed-tick CharacterBody2D/movement chassis plus compatibility facade for the still-unextracted loadout/melee/ranged/dodge/interaction/recovery domains. Input/aim, guard, action arbitration and semantic/body/playback presentation already have focused owners. F0/F1-F6 and Slice G are contracted in `design/04_architecture/OPERATOR_RUNTIME_ARCHITECTURE.md` and indexed in the Operator task-packet program.
- `custodian/game/actors/operator/input/`: **owns raw Operator input sampling and aim-source policy.** `OperatorInputRouter` is the only place Operator code reads `Input.*`; `OperatorInputFrame` is one fixed tick's intent, immutable, with edges that fire on exactly the tick that observed them; `OperatorAimController` owns the retained controller direction and the gamepad/keyboard/mouse priority. It does **not** own action legality, movement, or presentation -- the router answers what the player did, the aim controller what direction that means, and the gameplay authorities whether it is allowed. `InputPromptService` remains the single device-family authority. Enforced by `input_calls_outside_input_dir` in `operator_architecture_debt_audit.py`.
- `custodian/game/actors/operator/operator.gd`: **owns the tick spine.** `_physics_process` samples one input frame, runs `_advance_simulation` (clocks, input handling, state changes) and then `_advance_movement` (movement intent, attack drive, the sole `move_and_slide()`). `_process` is presentation only, enforced by `gameplay_mutation_in_process`. Externally supplied control enters through `process_input()` and is adopted by the next fixed tick, so there is one intent path rather than two.
- `custodian/game/actors/operator/presentation/operator_body_presenter.gd`: **owns BODY renderer exclusivity and visibility.** Exactly one registered body owner may be visible at a time; acquiring one atomically retires the rest, including lazily-created Vigil presentation rigs. It does **not** own semantic animation selection, animation identity resolution, gameplay action state, attack or posture timing, input, or movement. Body-layer `.visible` writes are permitted only under `operator/presentation/`, enforced by `operator_architecture_debt_audit.py`. Weapon/FX overlays remain owner-scoped cosmetics; the invariant is one body, not one `CanvasItem`.
- `custodian/game/systems/core/state/game_state.gd`: run failure, modal pause, compatibility state, and future persistent/run/world state pressure.
