## Purpose

This manifest tracks the production visual/audio inventory required to finish the Ash-Bell chain:

```text
surface lift ingress
    -> Forlorn-Ritualant Underground
    -> resolved north egress
    -> generated Ash-Bell Alpine Highlands
    -> generated Bridged Falls
    -> Lower Quarter approach / distant Station IX
```

It separates three classes deliberately:

1. **reuse / already published**: current production families that should be consumed rather than recreated;
2. **locked new assets**: enough contract exists now to name a family/state and exact dimensions or frame count;
3. **topology/design dependent**: the need is real, but exact state count/canvas/cadence must be derived from BF4/BF5 or human art review before publication.

Do not convert a topology-dependent row into a production requirement by guessing dimensions.

## Asset Pipeline V2 Rules

Every new/unprocessed image enters through:

```text
source master:
custodian/asset_drop/source_work/<area>/<family_id>/<state>_source.png

normalized intake:
custodian/asset_drop/inbox/<family_id>/<state>.png

family contract:
custodian/content/metadata/assets/families/<family_id>.asset.json
```

Runtime paths are generated by the family contract. Do not hand-copy source work into live runtime folders.

All image assets are RGBA PNG with true alpha unless a family is explicitly an opaque backdrop. Animation strips are horizontal unless the final family contract says otherwise. Gameplay collision/navigation/floor authority never comes from sprite alpha.

## Closeout Rule

This manifest is planning authority for **what the program expects to need**.

A family becomes production authority only when:

1. its owning packet is refreshed against live consumers/topology;
2. the exact family JSON is committed;
3. source is reviewed;
4. normalized intake is staged through the named inbox;
5. Asset Pipeline V2 publishes a healthy runtime result;
6. gameplay-scale evidence confirms the consumer uses the asset as intended.
